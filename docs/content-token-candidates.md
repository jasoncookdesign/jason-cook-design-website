# Content token candidates

**Retired 2026-10-19.** `[ENTRY-OFFER-NAME]` and `[PRACTICE-NAME]` were replaced with plain wording once the site had two engagement types with different first steps. The candidates below are kept as a record and are not rendered anywhere.

## `[ENTRY-OFFER-NAME]` — the paid first step

| Candidate | Rationale |
|---|---|
| System Diagnostic | Names the method and what it examines: the whole operating structure, as a bounded first step. |
| Architecture Diagnostic | Puts the practice's own word, "architecture", into the offer, so the name says which layer gets examined. |
| Situational Diagnosis | Ties the offer to the client's circumstances and to the home page's "the problem you actually have". |
| Problem Definition | Names the output, a written definition of the problem, which matches what the step delivers. |
| Organizational Diagnosis | Signals that the diagnosis covers people, process, information, AI, software, and infrastructure together. |

## `[PRACTICE-NAME]` — the name of the discipline (Capabilities page)

| Candidate | Rationale |
|---|---|
| Operating Architecture | Foregrounds a structure the client runs after handoff. |
| Systems Architecture | A recognized discipline term; engineering and operations readers know it. |
| Structural Architecture | Names the layer the practice works on: the structure underneath everything else. |
| Integrated Architecture | Names the property that sets the practice apart: strategy, design, specification, and implementation in one place. |
| Organizational Architecture | The trialled name without "Solution"; reads as a discipline beside enterprise, information, and business architecture. |
